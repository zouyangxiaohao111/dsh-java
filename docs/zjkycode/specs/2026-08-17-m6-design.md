# dsh-java:里程碑 6 设计 —— 多模块拆分 + 核心发布

- 日期:2026-08-17
- 状态:已批准(用户审核通过,"记录M6 需要将项目变为多模块项目")
- 范围:Gradle 多模块拆分、发布 dsh-cordis 到 Maven、PluginTestKit

## 1. 背景与目标

M1-M5 完成(168+ 测试)。当前是单模块工程,核心(`dev.dsh.cordis`)与 js/reload/loader 混在一个 build。M6 目标:

- **多模块拆分**,让其他项目直接 `implementation("dev.dsh:dsh-cordis")` 引入核心;
- **发布 dsh-cordis** 到 Maven(至少 MavenLocal),外部插件作者能 import 接口;
- **PluginTestKit** 测试骨架,外部插件可本地测。

## 2. 核心现状(已核实)

- `dev.dsh.cordis`(17 类 + util)**自包含**:只依赖 JDK + Jackson,**无反向依赖** js/reload/loader。
- 逻辑上已是"核心"(语义完整,测试全绿),**不需改逻辑**,只做结构拆分 + 发布。

## 3. 模块拆分

```
dsh-java(根,聚合)
  ├─ dsh-cordis      核心(现有顶层包 + util)——只依赖 JDK + Jackson
  ├─ dsh-js-host     GraalJS + NodeWorkerJsHost 桥(依赖 dsh-cordis + GraalJS)
  ├─ dsh-reload      热重载(依赖 dsh-cordis + dsh-js-host)
  ├─ dsh-loader      配置驱动加载(依赖 dsh-cordis + dsh-js-host + dsh-reload)
  └─ dsh-host        聚合(依赖全部)——"整个 harness"一键引入
```

## 4. 发布

- `dsh-cordis` 发布:`./gradlew publishToMavenLocal`(先本地,后 Maven Central)。
- artifact:`dev.dsh:dsh-cordis:0.1.0`(group/version 定案)。
- 外部插件作者:`implementation("dev.dsh:dsh-cordis:0.1.0")` → import dev.dsh.cordis.*。

## 5. PluginTestKit

- 测试基类:外部插件作者 `extends PluginTestKit`,写 `@Test` 本地跑插件(内部 new Context + 加载插件 + 断言)。
- 随 dsh-cordis 或 dsh-host 发布。

## 5.1 支持外部 jar 插件(M6 扩展)

loader(M5)加 `jar:` 源类型,同一个 cordis.yml 加载外部 jar 插件:

```yaml
plugins:
  - name: external-plugin
    source: jar:./plugins/external-plugin.jar     # 外部 jar 插件
    mainClass: com.example.ExternalPlugin          # 显式入口(可选)
  - name: counter
    source: java:dev.dsh.demo.CounterPlugin        # 源码(热重载)
  - name: echo
    path: node_modules/@koishijs/plugin-echo       # dsh JS(经桥)
```

**机制**(复用现成):
- `jar:` → 新 `URLClassLoader([jar], parent = 核心 CL)`(复用 `UrlPluginClassLoaderFactory`);
- 插件类发现:`mainClass` 显式 / 扫描 `implements Plugin` / ServiceLoader(`META-INF/services/dev.dsh.cordis.Plugin`);
- 实例化 → `registry.plugin(...)`(同一注册路径);
- 热重载:监听 jar 文件变更 → 新 CL 重新加载(M3 watch)。

**前提**:jar 插件编译需 `import dev.dsh.cordis.*` → 核心发布 Maven(§4);我们自建 jar(以 provided 带核心)不受限。
